## Задание 3.3 — мультиплексор 45-1 со стробированием

* Порты: `D(44 downto 0)` — информационные входы, `A(5 downto 0)` — адрес
  (2^6 = 64 ≥ 45), `STB` — строб, `Y` — выход.
* `STB = '1'` → `Y = D(A)`; `STB = '0'` → `Y = '0'`; адреса 45..63 не используются, для них `Y = '0'`.
* Тест: оба значения строба × все 64 адреса × оба значения выбранного входа
  («бегущая единица» / «бегущий ноль») = **256 наборов, 0 ошибок**.
  Полный перебор 2^52 наборов невозможен, но выбранные наборы проверяют каждую
  ветвь поведения мультиплексора.
* Синтез (Yosys, xc7): 15 LUT6 + 1 LUT5 + 1 MUXF7, 52 IBUF, 1 OBUF.

**Дополнительное задание** — `mux_demux_prio`: `MODE = 0` — мультиплексор, `MODE = 1` — демультиплексор;
`PRIO = 1` — канал выбирается по линиям запросов `REQ`, обслуживается запрос с наибольшим номером
(высший приоритет); `PRIO = 0` — обычная адресация по `SEL`; `STB` — строб; `CH`/`VALID` —
номер обслуживаемого канала и признак выбора канала. Тест: 65 536 наборов со сравнением
с эталонной моделью — **0 ошибок**.

## Задание 3.4 — нерегулярная схема (вариант 7)

Нумерация элементов (DD1–DD11) и связи восстановлены по схеме из приложения А:

| Элемент | Тип | Входы | Выход | t, нс |
|---|---|---|---|---|
| DD1 | N | x2 | nx2 | 1 |
| DD2 | N | x3 | nx3 | 1 |
| DD3 | O2 | x4, x2 | s_o2 | 2 |
| DD4 | NA3 | x2, x4, x1 | s_na3 | 3 |
| DD5 | NOAO2 | x3, s_na3, x1, s_o2 | **y3** | 4 |
| DD6 | NMX2 | A=s_o2, B=nx2, V=x3 | **y4** | 6 |
| DD7 | NAO22 | x3, x1, nx2, y3 | s_nao22 | 3 |
| DD8 | NO3 | x1, nx3, x4 | s_no3 | 4 |
| DD9 | NO4 | x4, x2, y4, y3 | s_no4 | 5 |
| DD10 | NO3A2 | s_no3, s_no4, x4, s_nao22 | s_no3a2 | 5 |
| DD11 | N | s_no3a2 | **y2** | 1 |
| — | провод | x2 | **y1** | 0 |

Минимизированные функции (они же — поведенческое описание):

```
y1 = x2
y2 = x2·x3·x4 ∨ ¬x1·x3·¬x4 ∨ ¬x1·¬x3·x4 ∨ x1·¬x2·¬x3·¬x4
y3 = x1·x2·¬x3·x4 ∨ ¬x1·¬x2·¬x3·¬x4
y4 = x2·¬x3 ∨ ¬x2·x3·¬x4
```

**Критический путь:** x2/x4 → DD3 (O2, 2) → DD6 (NMX2, 6) → DD9 (NO4, 5) → DD10 (NO3A2, 5) → DD11 (N, 1) → y2,
**2 + 6 + 5 + 5 + 1 = 19 нс**. При моделировании эта задержка проявляется на наборе `1010`.

Задержки, измеренные на каждом наборе (переход с предыдущего набора; перед первым набором подан `1111`):

| x1x2x3x4 | y1y2y3y4 | Задержка, нс |
|---|---|---|
| 0000 | 0010 | 6 |
| 0001 | 0100 | 6 |
| 0010 | 0101 | 11 |
| 0011 | 0000 | 10 |
| 0100 | 1001 | 7 |
| 0101 | 1101 | 6 |
| 0110 | 1100 | 11 |
| 0111 | 1100 | 0 (выходы не изменились) |
| 1000 | 0100 | 11 |
| 1001 | 0000 | 11 |
| 1010 | 0001 | **19** |
| 1011 | 0000 | 8 |
| 1100 | 1001 | 7 |
| 1101 | 1011 | 16 |
| 1110 | 1000 | 6 |
| 1111 | 1100 | 6 |

Обе архитектуры дают одинаковые установившиеся значения на всех 16 наборах (0 ошибок).
После синтеза обе модели сводятся к одинаковой схеме: 3 LUT (2×LUT4 + LUT3), y1 — прямая связь.

## Как запустить

Нужны GHDL ≥ 3.0 (моделирование), Python 3 + matplotlib (диаграммы),
Yosys + плагин ghdl (синтез, необязательно).

```bash
./scripts/run_sim.sh          # моделирование всех заданий -> build/*.vcd, build/*.log
python3 scripts/make_figures.py   # временные диаграммы -> report/img/
./scripts/synth_yosys.sh      # синтез под Xilinx 7-series -> synth/
```

VCD-файлы можно открыть в GTKWave (`gtkwave build/tb_circuit_v7.vcd`).

### Vivado

1. Создать проект для `xc7z010clg400-1` (Zynq-7010), добавить нужные `.vhd`-файлы
   (для 3.4 — все файлы из `task4_irregular/elements/` и `circuit_v7.vhd`),
   тестирующую программу добавить как Simulation Source.
2. Run Simulation → Behavioral Simulation; время моделирования: 3 мкс (3.3), 70 мкс (доп.), 500 нс (3.4).
3. Run Synthesis → Open Synthesized Design → Report Utilization / Schematic.

Или в пакетном режиме: `vivado -mode batch -source scripts/vivado_synth.tcl`.

> Для выбора архитектуры схемы 3.4 при синтезе в Vivado используется последняя
> описанная в файле архитектура (`Behavioral`); задержки `after` синтезатор игнорирует.
> Поскольку обе архитектуры логически эквивалентны, результат синтеза одинаков.
